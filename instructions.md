## Project Overview

**CyberGaming LB** is an e-commerce website for a used PS4 game store based in Lebanon. It lets customers:

- Browse 116 PS4 games with cover images, prices, genres, and editions
- Filter and search games by name, genre, edition type, and sort by price/date
- Add games to a shopping cart
- Place orders via WhatsApp with a pre-formatted message
- Submit a sell/trade request via WhatsApp
- View steelbook editions (18 rare steelbook games)

The site is fully **static** (no backend server needed). All game data is hardcoded. Orders go through WhatsApp messages. Prices are in USD.

**Social links:**
- Instagram: [@cybergaminglb](https://www.instagram.com/cybergaminglb/)
- WhatsApp: Currently placeholder (`wa.me/961`) - needs real number

## Game Data

All game data lives in `src/data/games.ts`. This file is the "database" of the site.

### Game Interface

```typescript
interface Game {
  id: string;          // URL-safe identifier (e.g., "god-of-war")
  title: string;       // Display name (e.g., "God of War")
  platform: string;    // Always "PS4"
  edition: GameEdition; // "Standard" | "Steelbook" | "Deluxe" | "Collector"
  condition: GameCondition; // "Like New" | "Good" | "Fair"
  price: number;       // USD price (e.g., 15)
  genre: GameGenre[];  // Array of genres (e.g., ["Action", "Adventure"])
  year: number;        // Release year
  image?: string;      // Path to cover image (e.g., "/covers/god-of-war.jpg")
  description?: string;
  isSteelbook: boolean;
  inStock: boolean;
}
```

## Cover Images

Cover images are stored in `public/covers/` and referenced in game data as `/covers/filename.jpg`.

- **206 files total** (mix of `.jpg` and `.svg`)
- More images than games because some have alternate filenames
- JPG images were downloaded from Steam's library assets
- SVG images are generated placeholders for games without Steam covers
- Images display at 3:4 aspect ratio in GameCard component
- If a game has no `image` property, a text placeholder shows the game title

### How covers were obtained

1. A script searched the Steam Store API for each game title
2. Downloaded the 600x900 library cover art from Steam CDN
3. For games not found on Steam, SVG placeholder covers were generated with the game title, colored gradients, and a PS4 label

## Cart System

The cart is implemented with React Context (`src/components/CartContext.tsx`).

### How it works

1. `CartProvider` wraps the entire app in `layout.tsx`
2. Cart state is an array of `{ game: Game, quantity: number }` items
3. State persists in `localStorage` under key `"cg-cart"`
4. On page load, cart is restored from localStorage
5. On every change, cart is saved to localStorage

### Available operations

- `addToCart(game)` - Adds a game (no duplicates; if already in cart, does nothing)
- `removeFromCart(gameId)` - Removes a game by ID
- `clearCart()` - Empties the cart
- `totalItems` - Count of unique games in cart
- `totalPrice` - Sum of all prices

### Cart UI

- Navbar shows cart icon with badge count
- GameCard has "Add to Cart" / "Remove" toggle button
- Cart page shows full list with checkout option
- Checkout opens WhatsApp with pre-formatted order message

## Building the Site

### Prerequisites

- Node.js 20+
- npm

### Build commands

```bash
# Install dependencies (first time or after package changes)
npm install

# Development server (live reload at http://localhost:3000)
npm run dev

# Production build (generates static HTML in out/ folder)
npm run build

# The built site is in the out/ folder:
# out/
# ├── index.html        (home page)
# ├── games.html        (games page)
# ├── sell.html          (sell/trade page)
# ├── about.html         (about page)
# ├── cart.html           (cart page)
# ├── 404.html            (error page)
# ├── covers/             (all cover images)
# └── _next/static/       (CSS, JS bundles, fonts)
```

### What `output: "export"` does

- Generates a fully static site (plain HTML/CSS/JS files)
- No Node.js server needed to run the site
- Can be hosted on any web server (Apache, Nginx, cPanel, XAMPP, etc.)
- Images must be unoptimized (`images: { unoptimized: true }`) since there's no server to optimize them

## Local Deployment (XAMPP)

### Setup

1. Clone the repo to your XAMPP htdocs:
   ```
   cd C:\xampp\htdocs
   git clone https://github.com/fadishehadeh/cybergaminglb.git
   cd cybergaminglb
   ```

2. Install dependencies:
   ```
   npm install
   ```

3. Build the site:
   ```
   npm run build
   ```

4. Copy built files to a servable folder:
   ```
   robocopy out site /E /PURGE
   ```

5. Start XAMPP Apache and visit: `http://localhost/cybergaminglb/site/`

### basePath for subfolder serving

Because the site is served from a subfolder (`/cybergaminglb/site/`) rather than the root, `next.config.ts` has:

```typescript
basePath: "/cybergaminglb/site"
```

This makes all CSS, JS, image, and link paths relative to that subfolder. **Remove this line when deploying to a domain root** (like `cybergaminglb.com`).

### Rebuilding after changes

Whenever you edit source files:
```bash
npm run build
robocopy out site /E /PURGE
```
Then refresh the browser.

## cPanel Deployment (GitHub Actions)

A GitHub Actions workflow (`.github/workflows/deploy.yml`) automatically deploys the site to cPanel whenever code is pushed to `main`.

### How it works

1. Push code to `main` branch on GitHub
2. GitHub Actions runs: checkout > install > build > rsync to server
3. The `out/` folder is synced to `~/cybergaminglb.com/` on the cPanel server

### Required GitHub Secrets

Set these in GitHub repo Settings > Secrets and variables > Actions:

| Secret | Description | Example |
|---|---|---|
| `DEPLOY_SSH_KEY` | Private SSH key for server access | (full private key content) |
| `DEPLOY_HOST` | Server IP or hostname | `198.187.31.120` |
| `DEPLOY_USER` | cPanel SSH username | `eurojeba` |
| `DEPLOY_PORT` | SSH port | `21098` |

### Workflow file (`.github/workflows/deploy.yml`)

```yaml
name: Deploy to cPanel
on:
  push:
    branches:
      - main

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm run build
      - name: Deploy to cPanel via rsync
        env:
          DEPLOY_SSH_KEY: ${{ secrets.DEPLOY_SSH_KEY }}
          DEPLOY_HOST: ${{ secrets.DEPLOY_HOST }}
          DEPLOY_USER: ${{ secrets.DEPLOY_USER }}
          DEPLOY_PORT: ${{ secrets.DEPLOY_PORT }}
        run: |
          mkdir -p ~/.ssh
          echo "$DEPLOY_SSH_KEY" > ~/.ssh/deploy_key
          chmod 600 ~/.ssh/deploy_key
          ssh-keyscan -p "${DEPLOY_PORT:-21098}" "$DEPLOY_HOST" >> ~/.ssh/known_hosts 2>/dev/null
          rsync -avz --delete \
            -e "ssh -i ~/.ssh/deploy_key -p ${DEPLOY_PORT:-21098} -o StrictHostKeyChecking=accept-new" \
            out/ \
            "${DEPLOY_USER}@${DEPLOY_HOST}:~/cybergaminglb.com/"
```

### Important notes for cPanel deployment

- The deploy target is `~/cybergaminglb.com/` (the addon domain's document root), NOT `~/public_html/`
- The `--delete` flag removes old files from the server that are no longer in the build
- When deploying to a domain root, **remove** the `basePath` line from `next.config.ts`
- An `.htaccess` file may be needed in `public/` for clean URLs on Apache:

```apache
DirectoryIndex index.html
RewriteEngine On
RewriteBase /
RewriteCond %{REQUEST_FILENAME} -f [OR]
RewriteCond %{REQUEST_FILENAME} -d
RewriteRule ^ - [L]
RewriteCond %{REQUEST_FILENAME}.html -f
RewriteRule ^(.*)$ $1.html [L]
RewriteRule ^ /404.html [L]
```

## Adding / Editing Games

### Adding a new game

1. Open `src/data/games.ts`

2. Add a new entry to the `games` array:
   ```typescript
   {
     id: "game-name",              // lowercase, hyphens, unique
     title: "Game Name",
     platform: "PS4",
     edition: "Standard",          // or "Steelbook", "Deluxe", "Collector"
     condition: "Good",            // or "Like New", "Fair"
     price: 15,                    // USD price
     genre: ["Action", "Adventure"], // 1-3 genres from the list
     year: 2020,                   // release year
     image: "/covers/game-name.jpg", // optional, path to cover image
     isSteelbook: false,           // true for steelbook editions
     inStock: true,                // false to show "Sold Out" overlay
   },
   ```

3. Add a cover image (optional):
   - Place a `.jpg` file in `public/covers/` named to match the `id` (e.g., `game-name.jpg`)
   - Ideal size: 600x900 pixels (3:4 ratio)
   - Set `image: "/covers/game-name.jpg"` in the game entry

4. Rebuild: `npm run build`

### Editing an existing game

- Change price: Edit the `price` field in `games.ts`
- Mark as sold out: Set `inStock: false` (shows "Sold Out" overlay, hides from games page, disables "Add to Cart")
- Change condition: Update the `condition` field
- Update cover: Replace the image file in `public/covers/` (keep the same filename)

### Removing a game

Delete the entry from the `games` array in `games.ts` and rebuild.

## Known Issues & TODOs

### Needs fixing

1. **WhatsApp number is placeholder** - All `wa.me/961` links need the real phone number (format: `wa.me/961XXXXXXXX`)

2. **Footer links don't use basePath** - The footer in `layout.tsx` (lines 31-33) uses raw `<a href="/games">` instead of Next.js `<Link>`. These links break when the site is served from a subfolder (XAMPP). They work fine when served from a domain root.

3. **basePath needs toggling** - `basePath: "/cybergaminglb/site"` in `next.config.ts` is needed for XAMPP but must be removed for cPanel/domain root deployment. This should be managed per environment.

### cPanel deployment issue (unresolved)

The cPanel server's Apache configuration was intercepting `index.html` with its default page (`defaultwebpage.cgi`) at the root URL, even though:
- Files were correctly uploaded to `~/cybergaminglb.com/`
- Other pages (`/about.html`, `/games.html`) worked fine
- DNS was correctly pointing to the server
- The `index.html` content was verified as correct on the server

This appeared to be a cPanel/Apache virtualhost misconfiguration that may require server admin intervention. Individual page URLs work; only the root URL (`/`) is intercepted.
